Running a Clash Check Against an IFC

Clash Check Manager compares your steel with the reference model. The skill is in scoping the check so the result is a list somebody will actually work through.

B Short Answer
Short answer

Clash Check Manager does this, and an IFC reference model is a supported source.

Insert the IFC first. A clash check has nothing to compare against until it is there.

  1. Insert the IFC as a reference model.
  2. On the Manage tab, click Clash check.
  3. Choose what the check includes in the clash check settings.
  4. Select objects first if you want a limited check.
  5. Run the check and wait for both progress bars.
  6. Work the list by status and by clash type.

Identical profiles in identical positions are not reported as clashes.

Issue Summary

Clash Check Manager is the tool for this. It finds objects that collide, or that are too close to each other, and it works inside native Tekla Structures models, inside reference models, and between the two.

That last part is what makes it useful when an IFC lands in your inbox. Insert the file as a reference model and your steel and their concrete, services or architecture can be checked against each other directly, without exporting anything to a third application.

The work is not in running the check. It is in setting it up so the result is a list you can act on, rather than nine thousand rows nobody will ever read.

What Can Be Checked Against What

FORMATS

Supported reference formats

IFC and IFC4, DWG and DGN, SKP, and .tekla files, with overlay models excluded. An IFC delivery from a consultant is the normal case.

TEKLA TO TEKLA

Another Tekla Structures model

It cannot be used directly. If you want to use another Tekla Structures model as a reference model, you must export it in the IFC format to be able to use it in clash check.

SCOPE

Between parts

Your own steel checked against itself. Worth running before you look at anyone else model, because your own clashes are the ones you can fix today.

SCOPE

Between reference models

Two consultant models checked against each other. Useful in a coordination role, less so when you only own the steel.

SCOPE

Objects in reference models

Clashes inside a single reference model. This finds problems in the file you were sent, which is a conversation with the sender rather than a change on your side.

SCOPE

Reference models and components

Your components checked against the reference geometry. This is where cleats, gussets and base plates meet somebody else duct.

Before You Start

ALIGNMENT

Get the origin right first

A reference model inserted at the wrong origin produces a clash list that is entirely fiction. Confirm alignment against a known grid intersection before running anything.

SIZE

Decide the scope honestly

A whole-model check on a large job takes time and returns a list nobody works through. Checking one floor, one gridline band or one trade at a time produces results people actually fix.

CLEARANCE

Agree the clearances

You can define a minimum distance value within the range from 500 mm to -500.0 mm. A negative value allows a defined overlap without reporting it. Units follow your file settings.

EXPECTATIONS

Know what a clash is not

Steel passing through a hole modelled by someone else as solid concrete is a clash in the software and correct in reality. Someone has to read the list with judgement.

OWNERSHIP

Decide who fixes what

Before you circulate a clash list, agree who owns each category. A list issued without that turns into a long email thread and no changed steel.

POINT CLOUDS

Surveyed geometry counts too

Point cloud clash checking is supported, which matters on refurbishment work where the existing structure is scanned rather than modelled.

The Procedure

  1. 1

    Insert the reference model

    On the File menu, select Import > Insert reference model, and place the IFC. Check the alignment before going further.

  2. 2

    Open Clash Check Manager

    On the Manage tab, click Clash check. The Clash Check Manager dialog opens.

  3. 3

    Set what the check includes

    In the clash check settings, select which combinations to check: Between parts, Between reference models, Objects in reference models and Between reference models and components.

    Switch off the combinations you do not own. A steel detailer checking clashes inside somebody else architectural model is generating homework for a different office.

  4. 4

    Set the clearances

    Define the minimum distance you want enforced, within the range from 500 mm to -500.0 mm. Zero finds only true collisions. A positive value also flags objects that are merely too close for access, welding or fireproofing.

  5. 5

    Choose all or selected

    To check everything, run the check with nothing selected. To limit it, select the model objects first, then run. Selected-object checks are how you keep a large job manageable.

  6. 6

    Run it

    Start the check and let it finish. A progress dialog shows completion for both Tekla Structures objects and reference model objects, so a check that appears stuck is usually still working through the reference side.

  7. 7

    Work the list

    Sort and filter the results, then work through them by category rather than top to bottom. Clicking a row takes you to the objects involved in the model.

Reading the Results

Each row in the clash list carries a state and a type. Both matter, and the states are what make a second run useful rather than a fresh start.

State What it means
ActiveA live clash, shown without a symbol.
NewFound in this run and not present in the previous one.
ModifiedThe clash existed before, and something about it has changed.
ResolvedMarked as dealt with. Your record that somebody has handled it.
MissingIt was in the previous run and is not in this one.
Clash type What it describes
ClashThe objects genuinely occupy the same space.
Is insideOne object sits entirely within another.
Min distanceNo collision, but closer than the minimum distance you set.

Run the check regularly rather than once at the end. The New and Modified states then tell you what changed since last time, which is far more actionable than a fresh list of everything.

The Limitation Worth Knowing

Identical objects in identical positions are invisible to the check

Tekla User Assistance states it plainly: clashes are not detected if the profiles and positions are identical. So a beam modelled twice in exactly the same place, or your steel duplicated in the reference model you were sent, will never appear in the clash list. Duplicate geometry needs a different check, and it is worth looking for it deliberately.

This catches people out most often when the consultant model already contains the steelwork. Their beam and your beam are the same profile in the same place, so the clash check stays quiet while the model contains everything twice.
