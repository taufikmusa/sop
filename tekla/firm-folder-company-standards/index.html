A Firm Folder for Company Standards

One shared folder, set once, so every model opens with your templates, components, catalogs and title blocks already in place.

A Question

“How do we set up our company standards so that every model has them, whether we open a new model or an old one? Library components, drawing templates and so on.”

Also asked as

  • Where do I put our company templates so that every model picks them up?
  • How do I set XS_FIRM, and what goes inside the folder?
  • Our drawing settings do not follow when someone else opens the model.
  • What is the difference between the firm folder and the project folder?
  • In what order does Tekla Structures look for settings files?

Generic form of a real customer question — names, company and project details removed. Tekla Structures 2026.

B Short Answer
Short answer

Company standards belong in a firm folder on a shared drive, not inside each model.

Tekla Structures reads that folder at every start, so new and existing models both pick it up.

  1. Create an empty folder in a shared location everyone can reach.
  2. On the File menu, click Settings, then Advanced options.
  3. In the File locations category, set XS_FIRM to that path.
  4. Restart Tekla Structures.
  5. Copy your templates, symbols and catalogs into the matching subfolders.

Files for one job go in XS_PROJECT, which takes priority over the firm folder.

Issue Summary

Every office reaches this question in the same way. Someone builds a good drawing template, a set of custom components and a report that finally looks right, and all of it lives in one model folder. The next model starts empty, and the work is redone or copied by hand.

Tekla Structures already has the answer built in. Settings are read from a stack of folders, and two of those layers exist specifically for you to fill: the firm folder, defined by the advanced option XS_FIRM, and the project folder, defined by XS_PROJECT.

The firm folder is the main container of files for the company. Its settings and files are meant to be used in all projects within the company. Put your standards there once, and every model on every machine that points at it starts with them.

How Tekla Structures Finds a Setting

Settings are managed in layers. The highest layer is hard-coded defaults you cannot edit, and each layer below it can override the one above. Knowing the order is what stops a mysterious “my template is not being used” problem.

Layer What it holds
Hard-coded defaultsPreset values included in the installation. The common environment is always included.
Common environmentPreset values in the installation directory.
Regional environmentPreset values suited for specific regional areas, such as your country environment.
XS_FIRMA folder, typically on a network drive, that loads settings for all users within your company.
XS_PROJECTA folder, typically on a network drive, that loads important settings for all users within a specific project.
Model templateLoaded once, when you create a new model, from the environment or from the network folders.
Model folderSaved locally when you add or edit settings while working.
Windows AppDataUser-specific settings related to the Tekla Structures user interface.

Read that as a search order: the more specific layer wins. A file in the model folder beats the project folder, which beats the firm folder, which beats the environment. That is the behaviour you want, because it lets one job deviate without anyone editing the company standard.

Before You Start

LOCATION

Somewhere everyone can actually reach

The firm and project folders are usually on a network folder or a shared file server that all users at the company can access. A path on one modeller machine is not a firm folder.

ACCESS

Read for everyone, write for a few

Give the whole team read access and keep write access with whoever owns the standards. A folder everyone can edit stops being a standard within a month.

OFFLINE

Think about laptops

If people work away from the office network, decide how they get these files. A firm folder on a path nobody can reach silently falls back to the environment defaults.

SCOPE

Firm is forever, project is for one job

Company title blocks, report templates and component libraries go in the firm folder. A client-specific title block for one job belongs in the project folder instead.

VERSIONS

Watch the version boundary

Files created in a newer Tekla Structures version are not always readable by an older one. If your office runs two versions side by side, plan for that before you consolidate everything.

BACKUP

Back it up like production data

Once this folder works, it is the office standard. It deserves the same backup treatment as your models, not the treatment a scratch folder gets.

The Procedure

  1. 1

    Create the empty folder

    Create an empty firm folder in a shared location. Something like a dedicated share, with a clear name, that will not be reorganised in six months.

  2. 2

    Point Tekla Structures at it

    On the File menu, select Settings > Advanced options. In the File locations category, define the path to the firm folder as the value of XS_FIRM.

    Do the same for XS_PROJECT if you want a project layer as well. The two are independent and you can use one without the other.

  3. 3

    Restart

    Restart Tekla Structures for the change to take effect. This is not optional and it is the single most common reason a correctly configured firm folder appears to do nothing.

  4. 4

    Create the subfolders you need

    The subfolder names below are fixed. Tekla Structures looks for specific names in specific places, so a template dropped loose in the root of the firm folder will not be found.

  5. 5

    Move your standards in

    Copy your existing files from the model folders where they were created into the matching subfolders. Work through one category at a time and test each before moving on.

  6. 6

    Test with a new model and an old one

    Create a fresh model and confirm the standards are there. Then open an existing model and confirm the same. Those are two different code paths and both need to work before you tell the team it is ready.

Which Subfolder Takes What

These subfolder names sit inside XS_FIRM or XS_PROJECT and are read automatically.

Subfolder What belongs there
\template\settingsTemplate and report settings.
\template\markMark templates used in drawings.
\SymbolsSymbol files and .dwg symbols used in drawings and templates.
\Drawing DetailsDrawing details saved as .ddf files.
\CustomInquiryReport templates used by custom inquiry.
\AdditionalPSetsAdditional IFC property sets.
\profil\Shapes and \profil\ShapeGeometriesShape catalog content.
\macros\Modeling and \macros\DrawingsMacros for the modelling side and the drawing side.
\ProjectOrganizerDataOrganizer categories and templates.
\PropertyRepository\TemplatesProperty repository templates.
Property files need to be copied deliberately

Property files are saved in the \attributes folder under the model folder while you work. They do not travel on their own. Copy the ones you want to standardise from there into the project or firm folder so they are reused instead of recreated.

The Files Most Offices Standardise First

DRAWINGS

Drawing layouts and title blocks

Layout files live in the \attributes subfolder in the model folder, and you can copy layout files to project or firm folders defined by the XS_FIRM and XS_PROJECT advanced options. This is how one title block reaches every job.

LOGOS

The company logo image

A logo used in templates needs its folder registered as well, through the advanced option DXK_SYMBOLPATH in Tekla Structures and the matching folder in the Template Editor preferences. Otherwise the image shows in the editor and not in the drawing.

COMPONENTS

The custom component library

Export your components as a .uel file and put it in the firm folder so every model has the same library, instead of passing files around by hand.

CATALOGS

Profile, material and bolt catalogs

Company additions to the bolt and profile catalogs belong here too, so a bolt someone added last year is still there on next year job.

REPORTS

Report templates

The material, bolt and shipping lists your office actually issues, kept in one place so the version everyone runs is the current one.

ORGANIZER

Organizer categories

The category structure your team sorts models by, so every job is organised the same way from day one.

When It Still Does Not Work

Almost every failure here is one of four things, and they are quick to check in order.

No restart. The advanced option was set and Tekla Structures was never restarted. Nothing is loaded until it is.

Wrong subfolder name. The file is in the firm folder but not in the subfolder Tekla Structures searches for that file type. The names in the table above are exact.

Something more specific is winning. An older copy of the same file is sitting in the model folder or the project folder and overriding the firm copy, exactly as the hierarchy says it should. Delete the local copy and test again.

The path is unreachable. A mapped drive that exists on one machine and not another produces standards that work for some people and not others, with no error message to explain why.
