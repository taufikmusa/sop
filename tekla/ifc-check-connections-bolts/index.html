Checking Connections and Bolt Sizes in an IFC

Insert it, drill down the hierarchy, inquire the object. Then face the harder question: was the information ever put in the file.

A Question

B Short Answer
Short answer

Insert the IFC as a reference model, then drill down and inquire the object you want.

What you can read is limited to what the sender exported. Tekla Structures cannot invent missing data.

  1. On the File menu, click Import, then Insert reference model.
  2. Activate the Select reference models switch.
  3. Add the Select objects in components switch for single objects.
  4. Point the model, hold Shift and scroll the middle mouse button.
  5. Right-click the object and select Inquire.
  6. Read the property sets listed for that object.

No bolts in the file usually means the sender left them out of the export.

Issue Summary

An IFC file is not a Tekla Structures model. It is a delivery of whatever the sending office chose to put in it, in whatever detail their export settings allowed. Checking connections and bolt sizes in one is therefore two different questions.

The first is mechanical: how do you get down to a single object inside a reference model and read its properties. That has a clear answer and this page walks through it.

The second is uncomfortable: is the information in the file at all. Very often it is not, and no technique in Tekla Structures will recover it. Knowing quickly which situation you are in saves an afternoon of hunting for data that was never sent.

What an IFC Can and Cannot Tell You

GEOMETRY

Shape is nearly always there

Plates, cleats, stiffeners and gussets arrive as solid geometry if the sender modelled them. You can see the connection, measure it, and clash check against it.

BOLTS

Bolts are optional, not automatic

Tekla Structures can export bolts with nuts and washers, so a file from Tekla Structures may well contain them. Whether they were included is the sender decision, made in their export settings.

PROPERTIES

Sizes come from property sets

A bolt diameter, grade or length is only readable if a property set carrying it was exported. Tekla User Assistance is explicit that model objects are exported on the basis of the export settings, including the property sets.

ENTITIES

Some parts are excluded deliberately

On the sending side, parts can be excluded from an export through their IFC entity settings. A missing member is not always a fault, and asking is faster than investigating.

SCHEMA

The schema affects what is possible

IFC export supports the IFC 2X3, IFC 4 and IFC 4.3 schemas. Ask which one you were sent when properties look thinner than you expected.

NOT NATIVE

It stays a reference model

Inserted IFC objects are reference objects, not Tekla Structures parts, until you convert them. They will not appear in your reports or numbering while they remain references.

Insert the File

  1. 1

    Open the model that will hold the reference

    Open the Tekla Structures model you want to check against, so the reference sits alongside your own steel.

  2. 2

    Insert it

    On the File menu, select Import > Insert reference model. The Reference models list and the Add model dialog open.

    You can also click the Reference models button in the side pane and then click Add model.

  3. 3

    Check the format

    IFC (.ifc) and ifcXML (.ifcXML) are supported, and you can use compressed (.ifcZIP) or uncompressed files. A zipped IFC does not need extracting first.

  4. 4

    Place it correctly

    Get the placement and origin right at insertion. Everything you check afterwards, connections and clashes included, is only as meaningful as the alignment between the two models.

Getting Down to a Single Object

This is where most people stall. Clicking an IFC model selects the whole thing, and the properties of the whole thing tell you nothing about one bolt.

What you want to select Switches to activate
The whole reference modelSelect reference models, plus Select components.
A single object inside itSelect reference models, plus Select objects in components.
An assembly inside itSelect reference models, plus Select assemblies.

There is a second route documented for walking the hierarchy, and it is the one worth learning because it works level by level. Activate the Select assemblies switch for assemblies, or the Select objects in assemblies switch for parts. Then point at the reference model, hold down Shift and scroll using the middle mouse button until you reach the hierarchy level where the reference object is.

A typical IFC hierarchy runs from IfcProject at the top, down through IfcBuildingStorey, to individual parts such as IfcWall or a steel member, and then to the objects below them.

Keep the cursor away from grid lines

Hierarchy scrolling does not work if the cursor is too close to a grid. If Shift and the middle mouse button appear to do nothing, move the pointer onto solid geometry and try again.

Reading the Connection and the Bolt Size

  1. 1

    Inquire the object

    With the object selected at the right hierarchy level, right-click it and select Inquire. The inquire dialog shows the native reference object properties and attributes.

  2. 2

    Read the property sets

    What appears is what the sender exported. For a bolt this is where a diameter, grade, length or standard would be, if the exporting office included the property set that carries them.

    Note the naming convention: an IFC property read in Tekla Structures carries an EXTERNAL. prefix in the inquire dialog. When you reuse the property name elsewhere, for example in conversion settings, write it as shown but without that prefix.

  3. 3

    Look at the connection geometry itself

    Even with no properties attached, the plates and bolt solids can be measured. Use the measuring tools against the reference geometry to confirm plate thickness, edge distances and bolt spacing.

  4. 4

    Add your own attributes if you are tracking the check

    Double-click the object to open the reference model object details, where you can view and modify user-defined attributes you have added. Those attributes can then be used for filtering, which is a practical way to mark what you have already checked.

  5. 5

    Report on it if you need a list

    To report a reference object attribute, inquire the object to see the property name, then in Template Editor add that property name to be reported in a Reference row. That turns a one-by-one check into a list.

When the Data Simply Is Not There

If the inquire dialog shows geometry and almost no properties, stop looking. The file does not contain what you need, and the fix is on the sending side.

Ask the sending office three specific questions, because vague requests produce vague files.

Were bolts included in the export? Tekla Structures can export bolts with nuts and washers, so if the source is a Tekla Structures model, the capability exists.

Which property sets were exported? Object properties reach IFC through property set definitions chosen at export time. Naming the properties you need is far more effective than asking for “more detail”.

Which schema was used? IFC 2X3, IFC 4 and IFC 4.3 differ in what they carry. Knowing which one you have explains a lot of apparent gaps.

A missing bolt is not evidence of a missing bolt

Never conclude from an IFC that a connection has no bolts. Absence in an IFC is a statement about the export settings, not about the steelwork. Confirm with a drawing or with the sender before raising it as a design issue.

If You Need Them as Real Parts

Reference objects can be converted into native Tekla Structures objects, either through direct conversion at insert time or through conversion change management for selected objects. Once converted, they behave like your own parts: they number, they report, and they appear in drawings.

That is a bigger decision than a check, and it changes who owns those parts in your model. For checking connections and bolt sizes, leave the file as a reference and inquire it in place.
