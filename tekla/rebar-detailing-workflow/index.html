B Short Answer
Short answer

Reinforcement has several methods, and the order of preference matters.

Components first, rebar sets second, manual bars last. Components update themselves when the concrete changes.

  1. Model or receive the concrete the bars belong to.
  2. Use a reinforcement component wherever one fits the shape.
  3. Use rebar sets on the Rebar tab for the rest.
  4. Pick standard shapes from the Rebar shape catalog.
  5. Number, then create the drawings and bending schedules.
  6. On the File menu, click Export, then BVBS.

Components are adaptive and update automatically when the reinforced part changes size.

Issue Summary

Rebar detailing is the workflow where doing it the quick way early costs the most later. Reinforcement is the part of a concrete model that changes the most often, because it moves every time the concrete it sits in moves.

Tekla Structures offers several ways to create reinforcement, and they are not equivalent. Some are adaptive and follow the concrete. Some are fixed and have to be redone by hand each time a section grows by twenty five millimetres.

Tekla User Assistance states the preference plainly: the most automated method is to use the various reinforcement components, and it recommends that you use reinforcement components to create reinforcement whenever possible. The reason is given in the same sentence: the components are adaptive, attached to a concrete part, and updated automatically if the dimensions of the reinforced part change.

The Methods, In Order of Preference

Method What it is When to reach for it
Reinforcement componentsAdaptive components attached to a concrete part, updated automatically when the part dimensions change.First choice, always. If a component fits the situation, use it.
Rebar setsBars grouped automatically by geometry, adaptive to concrete geometry and easy to modify using direct modification.Second choice, for geometry no component covers. Flexible and versatile.
Rebar shape catalogPredefined reinforcement shapes used to create a reinforcing bar group.For standard shapes where you want a bar group quickly.
Single bars and bar groupsBars created individually or as a group by hand.Last resort. Nothing updates itself, so every concrete change is manual rework.
Meshes and strandsReinforcement meshes, and prestressed strands.Where the product is mesh or prestressed rather than loose bar.
Rebar assembliesMultiple reinforcement objects combined, for example to create reinforcement cages.Where a cage is prefabricated and handled as one item.
The quick way is the expensive way

Hand-modelled bars look fastest on the first day. They are the reason a small section change on week six turns into two days of reinforcement rework. Spend the time finding a component or building a rebar set instead.

Before You Start

CONCRETE FIRST

Reinforcement needs something to sit in

Whether you model the concrete or receive it, the bars attach to concrete parts or pour objects. Getting the concrete stable first saves reworking the bars behind it.

SHAPES

Agree the bending shapes

Your shop and your code have a set of standard shapes. The Rebar shape catalog holds predefined shapes, and Rebar shape manager is where user-defined bending shapes are set up.

SCHEDULES

Decide the schedule format early

Bending schedules and pull-out pictures are built as templates in Template Editor. Getting the office standard one built and into the firm folder beats rebuilding it per job.

SETTINGS

rebar_config.inp controls drawing behaviour

Tekla Structures uses the settings in rebar_config.inp, in the system folder defined by XS_SYSTEM, the firm folder or the project folder, to define reinforcement-related settings in drawings, including area-specific bending schedules.

EXPORT

Confirm what the bending machines read

BVBS is the documented reinforcement export. Whether your shop reads BVBS 2.0 or 3.0, and what they expect in it, is worth asking before the first schedule is issued.

CONTEXT

Precast, cast in situ or both

The same reinforcement tools serve both, but the surrounding workflow differs. Cast in situ uses pour objects, precast uses cast units, and the bars follow whichever the job is.

The Workflow, Stage by Stage

  1. 1

    Get the concrete in place

    Model the concrete, or insert the designer model and work against it. Confirm the section sizes are settled enough to reinforce, because every later change propagates into the bars.

  2. 2

    Reach for a component first

    Look for a reinforcement component that covers the situation before modelling anything by hand. Components are attached to the concrete part and update automatically when it changes, which is the whole point.

  3. 3

    Use rebar sets for the rest

    On the Rebar tab, use Longitudinal, Crossing, By face or By guidelines. Each rebar set has at least one guideline defining the distribution direction, and leg faces define where the bar legs are created.

    Keep the Direct modification switch active. Rebar set property files use the .rst extension.

  4. 4

    Use the shape catalog for standard bars

    Create a reinforcing bar group by selecting a predefined reinforcement shape from the Rebar shape catalog. For shapes your code uses that are not there, define them in Rebar shape manager.

  5. 5

    Group into cages where appropriate

    Combine multiple reinforcement objects into rebar assemblies, for example to create reinforcement cages, where the cage is made up and handled as one item.

  6. 6

    Number

    Reinforcement numbers alongside the rest of the model. Rebar assemblies number as assemblies, and rebar set grouping takes cast units into account: if a cast unit consists of multiple parts, the bars are grouped within the cast unit instead of the parts.

  7. 7

    Produce the drawings and schedules

    Create the reinforcement drawings, and build the bending schedules or pull-out pictures as templates in Template Editor, controlling what information is shown.

  8. 8

    Export to the bending machines

    On the File menu, click Export > BVBS. The result is a text file in ASCII format with the extension .abs, carrying bent reinforcing bars, bar groups, meshes and hooks.

    Know which BVBS version you are sending

    BVBS 2.0 from 2000 is the base. Tekla Structures versions from 2021 onwards also support BVBS 3.0 from 2018, which adds coupler and thread data while keeping the syntax compatible with 2.0. A shop expecting one and receiving the other is a short conversation that is better had first.

Where Reinforcement Meets the Other Workflows

Rebar is the workflow that shows up inside all the concrete ones, which is why it has its own page rather than a paragraph in each.

In cast in situ work the bars belong to pour units: a pour object plus all the reinforcement, embeds and other objects that have to be in place before concrete can be poured. The pour view exists partly so that reinforcement spanning several parts can be modelled against the structure as built rather than as drawn.

In precast work the bars belong to cast units, and for automated production they have to be modelled according to production constraints, with longitudinal and cross wires differentiated and loose bars given their own classes so the factory can filter them.

In both, the export at the end is the same BVBS file. The difference is what the bars are attached to, not how they are made.
