The Consultant and Engineer Workflow

No machine at the end of this one. The deliverables are an analysis model, drawings and an IFC, and the skill is keeping the physical and analysis models in step.

B Short Answer
Short answer

A consultant uses Tekla Structures differently: the deliverable is information, not fabrication data.

The model feeds analysis, drawings and IFC. Those three are your output.

  1. Model the frame physically, as it will be built.
  2. Set the load modeling code, then create load groups and loads.
  3. Create filters to choose what belongs in the analysis model.
  4. Create the analysis model and check it.
  5. Create load combinations, then export to your analysis application.
  6. Import the results back and use them in connection design.

The physical model and the analysis model are separate, and both need looking after.

Issue Summary

Every other workflow in this set ends at a machine. A fabricator produces NC files, a precaster produces Unitechnik, a rebar shop produces BVBS. A consultant produces none of those, and that changes what the model is for.

For a consulting engineer the model is a source of three things: an analysis model to check the structure behaves, drawings that communicate intent, and an IFC that lets everyone else build against your geometry. The fabrication detail belongs to whoever fabricates.

That shifts the emphasis. Where a detailer worries about marks and machine data, a consultant worries about keeping two models in step: the physical model, which is what gets built, and the analysis model, which is a structural model created from a physical model, used for analysing structural behaviour and load bearing, and for design.

Two Models, One Job

The distinction catches people who arrive from a pure analysis package, where there is only one model and it is analytical.

Model What it represents What it is for
Physical modelThe structure as it will actually be built: real profiles, real positions, real connections.Drawings, quantities, coordination, and the geometry everyone else references.
Analysis modelA structural model created from the physical model, with members, releases, supports and loads.Analysing structural behaviour and load bearing, and design.

One physical model can carry several analysis models. You create filters to select the parts to be included in an analysis model, so a sub-model of one frame, or of one load case, is a normal thing to have rather than a workaround.

Before You Start

CODE

Set the load modeling code first

The load modeling code establishes the building code, the safety factors and the load group types. Set it before creating loads, because it governs how everything after it is interpreted.

SCOPE

Decide what is analysed and what is not

Not every part belongs in the analysis model. Filters decide what is included and which parts are treated as secondary, and getting that right is most of the work of a clean analysis model.

PACKAGE

Know which analysis application you are feeding

The workflow exports to an analysis application and imports the results back. Tekla Structural Designer is the documented example, and which others you can reach depends on your installation.

DELIVERABLE

Agree the IFC expectations early

IFC is your handover. What it carries depends on your export settings and property sets, so agree with the recipients what they need before the first issue, not after they complain.

DRAWINGS

GA drawings are the consultant output

Where a fabricator lives in assembly and single-part drawings, you live in general arrangement drawings. Set the layouts, title blocks and sheet sizes up once in the firm folder.

CHANGE

Plan for the design to move

A consulting model changes after it has been issued, repeatedly. Build it so that a revision is a re-run rather than a rebuild, and keep the numbering and drawing settings stable through it.

The Analysis Workflow

Tekla User Assistance sets the analysis workflow out as a sequence. Condensed, it runs like this.

  1. 1

    Set the load modeling code

    This establishes the building code, safety factors and load group types for the model.

  2. 2

    Create load groups, then loads

    Organise loads into groups first, then create the loads themselves. Groups are what load combinations are later built from.

  3. 3

    Create filters

    Filters select the parts to be included in an analysis model, and identify which parts are secondary. This is the step that decides whether your analysis model is the structure or a mess.

  4. 4

    Define the included objects and create the analysis model

    Choose which physical model objects are included, then create the analysis model from those parts and loads.

  5. 5

    Check and verify it in Tekla Structures

    Review the analysis model before it goes anywhere. Add primary beams where members need to be included, and modify properties such as end releases, support conditions and design parameters.

    Check the model here, not in the analysis package

    A release or support condition that is wrong in Tekla Structures will be wrong in the analysis application, and finding it there means coming back and doing this step anyway. Verify before you export.

  6. 6

    Create sub-models if you need them

    Alternative analysis models from the same physical model are normal. Use them rather than distorting one model to answer two questions.

  7. 7

    Create load combinations

    Build the combinations from the load groups created earlier.

  8. 8

    Export to the analysis application

    Transfer the model to the analysis software. Add any specialised loads that belong on that side rather than in Tekla Structures.

  9. 9

    Post-process and import the results

    Modify profiles and re-run the analysis as needed, then import the results back to Tekla Structures to examine them and use them in connection design. Import model changes back where the analysis moved sections.

The Deliverables Side

GA DRAWINGS

General arrangement drawings

Set up your sheet sizes, title blocks and layouts once, keep them in the firm folder, and produce GA drawings from the model rather than drafting them separately.

IFC

The coordination handover

Export all basic structural parts and objects on the basis of your export settings, including the property sets. IFC 2X3, IFC 4 and IFC 4.3 schemas are supported, so agree which one with the recipient.

REFERENCE MODELS

Working against other disciplines

Insert the architectural and services models as references, inquire their objects, and clash check against them. Those two jobs have pages of their own in this vault.

REPORTS

Quantities and checks

Reports read straight from the model database, which makes them a quick sanity check on the design as well as a source of quantities.

CLOUD LINK

Publish to Tekla Structural Designer

In Tekla Structures 2026 this is automatically available as a Preview feature, letting you publish to the cloud from Tekla Structures and receive the model from the cloud in Tekla Structural Designer. Being a preview feature, treat it as such on a live job.

ORGANIZER

Keeping track of a changing model

Organizer categorises the model by location and by property, and the Object Browser reports on it live. Useful when the design is still moving and you need to see what changed.

Where the Boundary Sits

The most common source of friction for a consultant on Tekla Structures is scope rather than software. The model can carry fabrication-level detail, and someone will eventually ask whether it should.

That is a commercial decision, not a technical one. What is worth knowing is that the tools are there: the same model that produced your GA drawings and IFC can carry connections, marks and machine data if your appointment extends that far. Nothing has to be remodelled to go further, which is a genuine advantage of detailing and analysis living in one place.

It also cuts the other way. If the fabricator is going to detail it, hand over the IFC and the drawings, and let their model be the one that carries marks. Two models both claiming to be the fabrication source is a problem no software setting fixes.
